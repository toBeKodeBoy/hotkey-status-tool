# HotkeyStats 版本功能清单

> 应用版本 v1.0–v1.4。与 `records.json` 的 `schemaVersion` 分开编号。当前原型对应设计文档 M0，数据格式已在开发分支升级为 schema v4，尚待新版桌面验收。
>
> v1.0–v1.3 只在 macOS 上实现，继续使用 Swift、AppKit 和 CoreGraphics。Windows 版放在 v1.4，不提前把现有原型改成跨平台框架。
>
> v1.0、v1.1、v1.2 的成品界面图示在 [原型图](原型图/README.md)。这些 GIF 按本清单绘制，不是当前原型的录屏。
>
> 各版都遵守现有原则：只统计带修饰键的组合键，监听只读，不拦截、不改写、不做宏。统计数据只写本机。v1.3 的更新检查是 macOS 上唯一计划中的网络例外，且不上传统计。

当前原型已经具备、后续版本只保留并收口的能力：

- 全局只读监听，组合键归一化为可读名称
- 过滤普通输入，以及仅 Shift 修饰的字符键；保留 Shift + 功能键
- 累计次数、今日次数、最近使用时间
- 菜单栏 Top 5、今日总量、组合键种类数
- 统计窗口、手动刷新、清空前确认
- JSON 持久化：退出、每 5 分钟、每新增 50 次保存；v1 迁移先备份，失败或未知版本不覆盖原文件
- 监听被系统禁用后自动重新启用

## v1.0 日常可开的菜单栏应用

把原型收成一台 Mac 上可以一直开着的应用。统计结果可信：按住不连击、暂停时不计、权限状态看得见。本版不记录应用，不做趋势、导出或公证。

### 功能

1. **应用包。** 构建产物为 `HotkeyStats.app`，`LSUIElement` 为真，无 Dock 图标。辅助功能 / 输入监控授权绑定到这个 App，而不是终端或 IDE。本地构建继续 ad-hoc 签名。
2. **单实例。** 已有实例在运行时，再次打开不产生第二个监听进程，并唤起已有实例的菜单或统计窗口。
3. **暂停与继续。** 菜单可暂停、继续统计。暂停期间移除或停用事件监听，不新增计数；继续后恢复监听。菜单栏图标区分「统计中」「已暂停」「无权限」。暂停状态在退出后保留。
4. **按住只计一次。** 同一次按下产生的系统重复事件只计 1 次。松开后再次按下才再计 1 次。
5. **权限状态。** 启动时用 `CGPreflightListenEventAccess()` 检查。未授权时菜单为警示态，文案与该项检查一致，并可再次打开对应系统设置。授权恢复后，菜单提供重新检查；若系统不允许当前进程热恢复，则明确提示需要退出后重开，并提供该操作。
6. **登录时启动。** 菜单开关，默认关闭。仅在以 `.app` 运行时可用。
7. **统计窗口可排序。** 表头可按累计次数、今日次数、最近使用时间排序。默认仍为累计次数降序。无数据时显示空状态，说明正在统计、已暂停或缺少权限。
8. **保存失败可见。** 写入或备份失败时不覆盖原文件，并在菜单给出失败状态。成功保存后清除该状态。

### 数据

- 继续使用 schema v2，不迁移、不改写已有 `records.json`。
- 暂停开关与登录启动项放在偏好设置，不写入统计文件。

### 验收

用户于 2026-11-07 确认桌面验收通过：权限撤销与恢复、登录后自动启动、暂停重启保持、重复启动唤起窗口，以及不同应用中的快捷键计数。此结论来自用户实测，适用于本次测试环境。


- 授权后按一次 `⌘C`，累计与今日各 +1；按住 `⌘C` 不连加。
- 暂停后按热键，两项次数不变；继续后再按，各 +1。
- 从菜单退出再启动，次数还在，暂停状态与退出前一致。
- 第二个实例不会同时写入同一统计文件。

### 本版不做

应用归属、忽略名单、趋势、时间筛选、冲突提示、键盘布局跟随、导出、Developer ID、公证、自动更新。

## v1.1 快捷键属于哪个应用

回答「这个组合键在哪些应用里用过、各用了多少次」。依赖 v1.0 的应用包、暂停和可靠计数。

### 功能

1. **记录前台应用。** 每次计入时读取 `NSWorkspace` 的前台应用，保存显示名和 bundle identifier。取不到前台应用时记为「未知应用」，仍计入组合键汇总。
2. **两个统计口径。** 保留不区分应用的组合键汇总。同时保存「组合键 × 应用」的累计次数、今日次数和最近使用时间。
3. **统计窗口按应用查看。** 可筛选某一个应用，也可按应用分组查看同一组合键。汇总行与筛选结果一致。
4. **菜单带来源。** Top 5 每一项显示该组合键累计次数最高的应用名。
5. **按应用忽略。** 设置中可勾选不统计的应用。被忽略应用中的热键不进入内存、不落盘。忽略名单可随时修改，不追溯删除已经记下的次数。
6. **旧数据不拆分。** 升级前的记录没有应用信息，界面显示为「未知应用」。不按猜测把历史次数分到具体应用。

### 数据

- schema 升到 v3。写入前先在同一目录备份；备份失败或文件版本高于当前支持版本时，不覆盖原文件。
- 忽略名单放在偏好设置。
- 应用显示名和 bundle identifier 只存在本机统计文件中。

### 验收

- 在文本编辑器中按 3 次 `⌘C`，再在浏览器中按 2 次 `⌘C`：汇总为 5，两个应用分别为 3 和 2。
- 把浏览器加入忽略名单后，在浏览器中按 `⌘C` 不增加任何计数；在文本编辑器中仍计数。
- 用现有 schema v2 文件启动后，原累计次数还在，应用列为「未知应用」，并生成备份。

### 本版不做

按日趋势、时间范围筛选、冲突判断、导出、布局跟随、公证和自动更新。

## v1.2 趋势与冲突

回答「最近 7 天和 30 天怎么变」，以及「同一个组合键是不是在多个应用里都高频出现」。依赖 v1.1 的应用维度。

### 功能

1. **按日累计。** 每个组合键、以及每个「组合键 × 应用」保留按日次数。跨天后历史日不再被今日计数覆盖。至少保留最近 30 个有记录的自然日。
2. **趋势图。** 统计窗口用 Swift Charts 展示所选组合键或当前筛选范围的 7 日和 30 日次数。无历史时显示空状态，不补造 0 以外的数据。
3. **时间范围。** 窗口可在「今日 / 7 日 / 30 日 / 全部累计」之间切换表格口径。菜单栏 Top 5 仍表示全部累计，今日总量仍表示今天。
4. **菜单栏今日第一名。** 今日次数最高的组合键变化时，图标旁显示该组合键的短名。暂停或无权限时不显示名次。
5. **冲突提示。** 同一组合键在至少两个未被忽略的应用中，各自的 7 日次数都达到可配置阈值时，在统计窗口标出。默认阈值写入设置并可关闭提示。提示只说明多个应用都在高频使用，不判断哪个应用会胜出。
6. **键名策略。** 默认仍是 ANSI 物理键位。设置可改为按当前键盘布局生成显示名（`UCKeyTranslate`）。只影响之后新记入的事件；已保存的名称不批量改写。未知键仍可显示为 `Key(n)`。

### 数据

- schema 升到 v4，迁移规则与 v1.1 相同：先备份，失败则不覆盖。
- 原有累计次数保留。升级前没有日明细的历史只进入「全部累计」，不分配进某一天。
- 冲突结果随查询计算，不单独落盘。

### 验收

- 连续两天使用同一组合键后，7 日图上是两天各自的次数，累计次数等于各日之和加上升级前无法分日的历史累计。
- 文本编辑器和浏览器的 `⌘C` 在 7 日内都超过阈值时，窗口出现冲突标记；关闭提示后标记消失，计数不变。
- 切换布局键名后，新按的键使用新名称；旧记录名称保持不变。

### 本版不做

导出、匿名报告、Developer ID、公证、自动更新。Option 参与的字符输入仍可能被记为热键，本版不承诺从语义上排除。

## v1.3 导出与独立分发

在本机查看之外，能够导出一份可留档的报告，并把应用装到另一台 Mac。依赖 v1.2 的日明细和应用维度。

### 功能

1. **导出当前视图。** 按统计窗口当时的应用筛选和时间范围，导出 CSV 与 JSON。导出前显示将包含的字段。
2. **匿名化报告。** 单独导出一份报告，默认去掉应用显示名、bundle identifier 和本机路径。保留组合键、次数、日期和冲突标记所需的应用个数。设置中可明确选择保留应用名，默认关闭。
3. **签名与公证。** 发布包使用 Developer ID 签名并完成公证。提供磁盘镜像或压缩包，以及安装后首次授权的说明。Gatekeeper 可打开该发布包。
4. **自动更新。** 使用 Sparkle 检查更新。这是项目里唯一的网络功能：只访问更新源，不发送统计、应用列表或按键记录。菜单可关闭更新检查，默认关闭，由用户打开。
5. **本地说明。** 应用内有一页隐私说明，写明采集范围、保存位置、忽略名单、导出字段，以及更新检查开启后会访问网络。

### 数据

- 不升级 schema。导出是只读变换，不修改 `records.json`。
- 更新检查的开关放在偏好设置。

### 验收

- 默认匿名导出文件中搜不到统计里出现过的应用显示名和 bundle identifier。
- 关闭「保留应用名」时，CSV 与 JSON 的行为与匿名报告一致；打开后才包含应用字段。
- 未签名的本地开发包仍可按 v1.0 的方式 ad-hoc 运行。发布包在另一台未安装开发工具的 Mac 上通过 Gatekeeper 打开。
- 更新检查关闭时，应用进程不发起更新连接。

### 本版不做

App Store 分发、账号体系、统计上传、同步、按键改写、宏，以及 Windows 版。

## v1.4 Windows 日常统计

第一版 Windows 应用，对齐 macOS v1.0 的日常统计，不把 macOS v1.1–v1.3 的应用归属、趋势、导出和公证搬过来。macOS 版继续按原技术栈维护，两边的统计文件使用同一套 schema。

### 功能

1. **系统托盘应用。** 常驻通知区域，无主任务栏窗口。托盘菜单提供 Top 5、今日总量、组合键种类数、打开统计窗口、暂停与继续、退出。
2. **只读全局监听。** 使用低级键盘钩子读取按键，处理完必须把事件原样传给下一个钩子。不吞掉、不改写按键。
3. **与 v1.0 相同的计数规则。** 只统计带修饰键的组合键；过滤普通输入和仅 Shift 修饰的字符键；同一次按住产生的重复事件只计 1 次；暂停期间不监听、不新增计数。
4. **单实例与暂停。** 已有实例运行时，再次打开不创建第二个钩子。暂停状态退出后保留。托盘图标区分「统计中」「已暂停」「监听失败」。
5. **本机 JSON。** 统计写入 `%AppData%\HotkeyStats\records.json`，schema 与当时的 macOS 版一致。保存时机仍是退出、每 5 分钟、每新增 50 次。写入失败不覆盖原文件。
6. **键名对照。** Windows 显示 `Ctrl`、`Alt`、`Shift`、`Win`。统计主键使用与平台无关的修饰键和键码，避免同一组合在 macOS 与 Windows 上因符号不同被存成两条。界面各自显示本平台习惯的符号。
7. **登录时启动。** 托盘开关，默认关闭。

### 数据

- 不单独发明 Windows schema。v1.4 发布时 macOS 若仍是 schema v2，Windows 也写 v2；若 macOS 已升到更高版本，Windows 按该版本写入，并沿用先备份、失败不覆盖的迁移规则。
- 不在这一版做两台电脑之间的同步。文件格式对齐，是为了以后导出和阅读可以共用解析规则。

### 验收

- 在记事本中按一次 `Ctrl+C`，累计与今日各 +1；按住不连加。
- 暂停后按热键，次数不变，被按下的键仍正常到达记事本。
- 退出再启动，次数和暂停状态都还在。
- 第二个实例不会同时写同一个统计文件。

### 本版不做

前台应用归属、忽略名单、趋势、时间筛选、冲突提示、导出、自动更新，以及把 macOS 原型重写成跨平台 UI。Linux 不在这一版。
